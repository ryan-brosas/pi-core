## Must-Haves

### Observable Truths

1. A planner changing a module boundary is told to include a **Boundaries and Testability** section, while unrelated plans are told to omit it.
2. A proposed seam is rejected unless the plan names a substitution need, an enabling point, and a real alternative implementation.
3. A gray-box verification exception records the internal knowledge used and why externally observable behavior is insufficient; gray-box knowledge does not authorize mocking internals.
4. PRD Success Criteria describe externally observable behavior without constraining Proposed Solution or Technical Context.
5. Deep-module guidance no longer treats an interface alone as a test seam; an enabling point must be able to select another behavior.

## Boundaries and Testability

Black-box and gray-box are verification perspectives, not module-design categories.

### Module Boundaries

| Boundary | Hidden decision | Public contract |
| --- | --- | --- |
| Lifecycle planning surface | Which decisions every generated implementation plan must record | Phase 7 Required Plan Header in `.pi/prompts/plan.md` |
| Reusable planning skill | How planners structure those decisions outside the slash prompt | Plan Template in `.pi/skills/planning-and-task-breakdown/SKILL.md` |
| Requirement versus design detail | Acceptance behavior versus implementation context | Success Criteria only in `.pi/templates/prd.md` |
| Module-design teaching | What qualifies an interface as a substitutable test seam | Test Seams section in `.pi/skills/deep-module-design/SKILL.md` |

### Proposed Seams

None. This feature changes documentation contracts and their tests; it has no volatile runtime dependency, enabling point, or real alternative implementation. Introducing an interface or adapter would fail the feature's own seam gate.

### Gray-Box Exceptions

| Verification | Internal knowledge used | Why externally observable behavior is insufficient | Stability |
| --- | --- | --- | --- |
| `skill-system.test.ts` contracts | Markdown headings, canonical file paths, and stable semantic phrases | There is no deterministic black-box harness that executes `/plan` and inspects model-generated plans; direct surface inspection is the retained executable contract | Stable workflow surface |
| Scoped PRD assertion | Locations of Success Criteria, Proposed Solution, and Technical Context headings | The requirement is specifically about where policy text lives, so whole-file behavior alone cannot detect scope leakage | Stable template structure |

These exceptions inspect published repository surfaces, not private runtime calls, and do not justify mocking internals.

## Research Basis

- Fowler's Legacy Seam definition requires both a place where behavior can change without editing that place and an enabling point where one behavior is selected over another.
- NIST defines gray-box testing by partial knowledge of internal structure and implementation detail, supporting its treatment as a verification perspective.
- Google Testing Blog guidance favors behavior and public-API tests over implementation-detail tests, supporting the explicit warning against using gray-box knowledge to mock internals.
- Full citations and the earlier cross-check are retained in `.pi/artifacts/seam-blackbox-greybox-workflow/research.md`.

```ts
test("planning boundaries and testability contract is conditional", () => {
  const surfaces = {
    "plan prompt": readRequired(".pi/prompts/plan.md"),
    "planning skill": readRequired(".pi/skills/planning-and-task-breakdown/SKILL.md"),
  };

  for (const [label, text] of Object.entries(surfaces)) {
    assert.match(text, /Boundaries and Testability/i, `${label} must name the section`);
    assert.match(
      text,
      /only when[^\n]*introduces or changes[^\n]*module boundary[^\n]*omit it otherwise/i,
      `${label} must make the section conditional`,
    );
    assert.match(text, /black-box and gray-box are verification perspectives, not module-design categories/i);
    assert.match(text, /substitution need/i);
    assert.match(text, /enabling point/i);
    assert.match(text, /real alternative implementation/i);
    assert.match(text, /if any[^\n]*missing[^\n]*(?:do not|must not) add[^\n]*seam/i);
    assert.match(text, /gray-box exceptions?/i);
    assert.match(text, /internal knowledge/i);
    assert.match(text, /why externally observable behavior is insufficient/i);
    assert.match(text, /gray-box knowledge does not justify mocking internals/i);
  }
});

test("PRD success criteria describe externally observable behavior", () => {
  const prd = readRequired(".pi/templates/prd.md");
  const section = (heading: string): string => {
    const start = prd.indexOf(heading);
    assert.notEqual(start, -1, `missing PRD section: ${heading}`);
    const rest = prd.slice(start + heading.length);
    const next = rest.indexOf("\n## ");
    return rest.slice(0, next === -1 ? undefined : next);
  };

  assert.match(section("## Success Criteria"), /externally observable behavior/i);
  assert.doesNotMatch(
    `${section("## Proposed Solution")}\n${section("## Technical Context")}`,
    /externally observable behavior|black-box|gray-box/i,
    "observable-behavior policy must remain scoped to Success Criteria",
  );
});

test("deep module design requires an enabling point for a test seam", () => {
  const skill = readRequired(".pi/skills/deep-module-design/SKILL.md");
  assert.doesNotMatch(skill, /The interface IS the test seam/i);
  assert.match(
    skill,
    /An interface becomes a test seam only when an enabling point can select one behavior or a real alternative\./i,
  );
});
```
